## Findings (crash gate verdicts)
**Confirmed** (reproduced and reviewed by an independent Crash Verifier):
- **Medium: 1-byte heap over-read encoding an all-zero big number** (2 fingerprints, one root cause).
  - `QCBOREncode_Private_SkipLeadingZeros` sets the length to 1 without moving the pointer back from one past the end.
  - The out-of-bounds byte is copied into the encoded output (`UsefulOutBuf_AppendUsefulBuf`) or read by `BigNumberToUInt`.
  - Reachable from the public API: `QCBOREncode_AddTBigNumber`, `AddTBigNumberNoPreferred`, and the decimal-fraction / big-float big-mantissa functions. A standalone program using only the public API reproduces it under ASan.
  - Fix patch: return a 1-byte view of the last zero byte.
- **Low: out-of-range shifts in `ieee754.c`** (3 fingerprints).
  - `IEEE754_DoubleToSingle` (negative shift, and shift ≥ 64) and `IEEE754_SingleToHalf` (negative shift) shift before checking the exponent range.
  - Reached by encoding floats and doubles, and by decoding untrusted CBOR in shortest-float conformance modes. The bad result is discarded, so the effect is undefined behavior only.
- **Low: pointer overflow in `UsefulOutBuf_Compare`.** It forms pointers from out-of-range offsets, although the header says any offset is safe.
- **Low: uninitialized values read after a decode error.**
  - `QCBORDecode_Private_GetItemInMap` reads `uOffset` uninitialized.
  - `QCBORDecode_GetTEpochDate` and `GetTEpochDays` copy an uninitialized value to the caller's output.

**Needs validation** (4): `GetTEpochDateInMapN/SZ` and `GetTEpochDaysInMapN/SZ` show the same uninitialized-output pattern. E-ACSL marks a whole-struct copy as initialized, so it cannot witness these; the validation plan is MSan.

**Rejected:**
- **13 E-ACSL toolchain artifacts:** by-value struct parameters are never marked initialized.
- **3 harness-induced:** cases 48, 129 and 166, all repaired.

## Pipeline issues found (not fixed in this run)
- **Most serious: E-ACSL never marks by-value formal parameters initialized.** The generated code has `__e_acsl_store_block(&formal)` but no `__e_acsl_full_init`, so every function taking a struct by value fails its first `\initialized` check whatever the input.
  - It caused 13 false candidates.
  - It made E-ACSL fuzzing skip 55 of 179 dispatch cases almost at once, so E-ACSL coverage on this run is much shallower than it should be. The sanitizer engine was unaffected.
  - A verifier reproduced it on a 15-line standalone program with the pipeline's E-ACSL flags.
  - Possible fix: a post-instrumentation pass that adds `__e_acsl_full_init` after each formal's `store_block`, or drop `\initialized` RTE checks on formals.
- E-ACSL marks the destination of a whole-struct copy as initialized whatever the source, so uninitialized data that travels through a struct copy is invisible to it. This is why 4 candidates stay at needs validation; an MSan build would catch them.
- `eva-tune` should skip tuning when the base run's elapsed time is already at or over the rung cap.
- The timeout fallbacks (`cvalue_fast`, `cvalue_imprecise`) should not run inside tuning rungs: they are less precise than the base, so they cannot help.
- The timeout message gives the fallback's 900 s instead of the rung's 7200 s.
- **Blocks Phase 3:** the dual-oracle guardrail rebuilds with `\initialized` checks, so the by-value-parameter artifact turns every prover and architect check into `code_fault` on unchanged code. The by-value fix above would unblock it. Until then, `--no-fuzz-rte-initialized` is the only workaround, and it drops the initialization checks.
- An architect task can be assigned a header that only includes others (`qcbor.h`). Header selection should pick the headers that declare the module's functions, or give one architect to each of them.
- A harness repair that only narrows fuzz inputs still forces a full Eva re-run (2 h here): the Eva driver and the fuzz dispatch share one file, and the Eva cache is keyed on it.
- The repair task lists which crash fingerprints are harness-induced, but not which dispatch cases still reach them. Repair 1 fixed case 48 and missed cases 57 and 170, which reach the same fingerprint through a wrapper function, and the gap only showed after a 2.5 h module re-run. The repair task could list every case whose reproducers hit each fingerprint.
- The coverage replay counts no execution for an input that aborts. An entry point reached only by crashing inputs therefore fails the dynamic reach gate, and the only way through is an exemption. The replay should record the crash's stack as executions, or flush the counters before aborting.
