# API reach: the tweetnacl fixes, generalized (2026-11-08)

Branch `phase0-redesign`, local, not pushed. Four fixes in the order agreed, plus four found by running them.

## The problem

tweetnacl's pinned harness called `crypto_hash` only: 24 of its 25 API entry points were accepted reach gaps, and with no test command it got no seeds. Any target without tests and with a hand-pinned harness was in the same position, and the benchmark could not see it.

## What changed

| Commit | Fix |
| :--- | :--- |
| `c5a8381` | **4.** `generate_harness.py --api` (`scripts/api_harness.py`): a dispatch harness with one case per entry point of the module's scope, arguments built from the model's signatures and formals. The benchmark records `api_reach` per target; `compare` flags fewer reached as a regression. tweetnacl's manifest harness is now `{"generate": "api"}`, with no accepted gaps. |
| `926e657` | **1.** No test command: `seed_harvest.py record` relinks the project's non-test executables that define API functions and runs each once (no arguments, empty stdin, 60 s). The benchmark runs the seeds stage whenever the model is ok. |
| `55df295` | **2.** `phase0_dump.ml` records, per call, the bytes left in the object a pointer argument points into (`buf`, `&buf[4]`, `buf + 4`, `&key`); the model aggregates them per callee as `param_sizes`. The harness sizes keys and nonces from it, and the recorder records such buffers (kind `a`). |
| `0d5efe4` | **3.** The recorder logs pointer addresses; `workspace/seed_records/traces.jsonl` keeps each process's calls in order. `--api` turns calls that share a buffer into sequence cases. |
| `1e6c07b` | Found on the run: a call into another module (`randombytes`) dropped the whole chain; and a sequence sized a shared output from the trace's recorded bytes (1 byte, for a buffer box writes `mlen` bytes into). Foreign calls are filtered out; a lone output of a call whose input length comes from the fuzz input gets a spare buffer; shared buffers are sized from the model only. |
| `47d3615` | Found on the run: `api_reach` counted a unit's reach-gate view on top of its harness rows (tweetnacl 52 entry points instead of 26). |
| `67c2a3e` | Found on the run: `compare` called tweetnacl a regression (Unknown 4 → 92) because Considered valid rose by 5, although properties checked rose by 869. A rise in assumptions no larger than the growth in checked code is now read as more code. |

Unit suite, ruff and mypy pass after each commit.

**New finding on tweetnacl:** the fuzz campaign reports `car25519` line 282, `o[i]-=c<<16` with `c < 0`: a left shift of a negative value, undefined behaviour. Both crash inputs are seeds (the second is the demo's own `crypto_box` call, message "This is a cross-platform test of crypto_box/crypto_box_open in TweetNaCl."), so ordinary use triggers it. It is reached through `crypto_box`, `crypto_scalarmult` and the signing functions, none of which the old harness called. It is a known TweetNaCl defect (later versions multiply instead of shifting); compilers in practice produce the intended result. It is a candidate, not yet a verified finding.

**Sequence case:** the run above used images built before `1e6c07b`, so its harness has no sequence case. Re-planned on that run's data, the fixed generator gives one: keypair ×2 → box → open, keys shared, nonce from the input, box's output a spare buffer passed to open. A rerun on rebuilt images is the check (below).

## Limits and findings

- **Executables run without arguments only.** Tools that need a file (x509-parser) or crash without arguments (qlz) record nothing. Passing the tree's data files as arguments would help only where the tree ships some; x509-parser ships none.
- **Eva cost.** The whole-API harness makes tweetnacl's Eva 200× slower (30 min). The benchmark's tweetnacl target now costs about 32 min instead of 2.5.
- **Fingerprints carried UBSan's runtime value (fixed, `684052f`).** The same `car25519` site gave two UBSan fingerprints differing only in the shifted value (-2806, -19345), plus the E-ACSL one. UBSan predicates now replace runtime values by `N` (the message as printed is kept in `message`). MINMEA-01 and MINMEA-03 were recorded from such messages; their fingerprints in the manifest and the minmea write-up are recomputed. Recall does not match by fingerprint, so it is unaffected; a compare against an older baseline shows those two candidates once as gone and new.
- **New baseline.** These runs are not in `phase0-r1`; tweetnacl's numbers move by design. Record a baseline after the merge.

## Rerun

Run `api2-oscs-tweetnacl`, on images rebuilt after `1e6c07b` (wall 1955 s).

- **Sequence case: present.** Case 25 calls keypair ×2 → box → open, as planned above. API reach 25 of 26 (1 exempt), 3 seeds.
- **Candidates:** the two `car25519` shift fingerprints, now one per site and engine (the UBSan value no longer splits them).
- **Compare vs `api`:** Eva Unknown 92 → 96, functions with an Unknown 17 → 18 (`crypto_sign_ed25519_tweet_open`): the sequence case drives `open` with a real box.
- **Status `partial`, `queue` rc=1: an artifact of the run, not of the fixes.** The run mounts the live `scripts/` directory, and the remediation steps R1/R2/R8 were being edited while it ran. Its reach check ran before R1's change (its rows carry no `dag_digest`), its gate check after it, and R1 makes digest-less rows fail by design. Validation V, on a clean HEAD, is the real check.
