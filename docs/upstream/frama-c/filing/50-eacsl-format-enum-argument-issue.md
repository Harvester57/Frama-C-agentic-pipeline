# [E-ACSL] --validate-format-strings: Assertion failed in functions.ml:156 on enum arguments to printf-family functions

<!-- Everything below this line is the issue description. -->

### Summary

With `--validate-format-strings` (`-e-acsl-validate-format-strings`), passing an `enum` value to
`printf`, `fprintf`, `sprintf`, `snprintf`, `dprintf`, or `syslog` crashes Frama-C during E-ACSL
instrumentation with `Assert_failure` in `plugins/e-acsl/src/libraries/functions.ml`, line 156.
Passing a pointer to an `enum` (such as `&s` for `%n` when the enum's underlying integer type is
`int`, or a mismatched `%p`/`%s`) aborts E-ACSL with `Options.fatal`
(`unexpected argument type in printf`) instead of letting the runtime format check handle it.

### Steps to reproduce the issue

`enum_printf.c`:

```c
#include <stdio.h>

enum Color { RED = 0, GREEN = 1 };
enum Err { ERR_FAIL = -1, ERR_OK = 0 };

int main(void) {
  enum Color c = GREEN;
  enum Err e = ERR_FAIL;
  printf("%u %d\n", c, e);
  return 0;
}
```

```sh
gcc -Wall -Wextra -Wformat=2 -Wformat-signedness enum_printf.c -o plain && ./plain
e-acsl-gcc -q -c -M -G gcc --validate-format-strings -o m.c -O m enum_printf.c && ./m.e-acsl
```

(`-M` is `--full-mtracking`, to avoid the unrelated stop on literal format strings tracked in
#2821.)

For the enum-pointer case (`enum_ptr.c`):

```c
#include <stdio.h>

enum Err { ERR_FAIL = -1, ERR_OK = 0 };

int main(void) {
  enum Err e = ERR_OK;
  printf("hi%n\n", &e);
  return e != 2;
}
```

```sh
gcc -Wall -Wextra -Wformat=2 -Wformat-signedness enum_ptr.c -o plain_ptr && ./plain_ptr
e-acsl-gcc -q -c -M -G gcc --validate-format-strings -o mp.c -O mp enum_ptr.c && ./mp.e-acsl
```

### Expected behaviour

`enum_printf.c` instruments, compiles, prints `1 -1`, and exits 0 (and a mismatched directive such as
`printf("%s\n", e)` or `printf("%lu\n", c)` instruments cleanly and aborts at run time with the
usual format-type mismatch diagnostic).

`enum_ptr.c` instruments, compiles, prints `hi`, sets `e = 2`, and exits 0 (since `enum Err`'s
underlying integer type is `int`, making `enum Err *` compatible with `int *` under C11 6.7.2.2p4
and 6.7.6.1p2; gcc 14 accepts both files with `-Wall -Wextra -Wformat=2 -Wformat-signedness`). A
mismatched enum pointer such as `printf("hi%n\n", &c)` (`unsigned int *`) or `printf("%p\n", &e)`
instruments cleanly and aborts at run time.

### Additional information (optional)

**Cause.** In `src/kernel/internals/typing/cabs2cil.ml` (`default_argument_promotion`, line 3847),
variadic argument promotion keeps `TEnum ei` as `mk_tenum ei` rather than rewriting it to
`TInt ei.ekind`. When `Functions.Libc.get_printf_argument_str`
(`plugins/e-acsl/src/libraries/functions.ml`, lines 150-158) inspects each variadic argument's
unrolled type, `TEnum _` is grouped with `TVoid`, `TArray _`, `TFun _`, `TNamed _`, `TComp _`, and
`TBuiltin_va_list` in `assert false`. Similarly, `get_pkind_str` (lines 131-147) only handles
`TInt _` and `TVoid`, so any `TPtr (TEnum _)` falls into `Options.fatal`.

Other parts of E-ACSL already reduce `TEnum { ekind }` to `ekind` (`analyses/typing.ml`,
`code_generator/assert.ml`, `code_generator/translate_terms.ml`, `libraries/interval_utils.ml`).

**Fix.** In `Functions.Libc.get_printf_argument_str`:

- Handle `| TEnum { ekind } -> get_ikind_str ekind ^ acc` in `param_str`.
- Make `get_pkind_str` recursive and add
  `| TEnum { ekind } -> get_pkind_str a (Cil_const.mk_tint ekind)` (matching
  `libraries/interval_utils.ml`).

Note that `Cil.intKindForValue` only assigns the ten standard signed/unsigned integer kinds
(`IUChar` through `IULongLong` and `ISChar` through `ILongLong`) to `enum.ekind`, so both helpers
cover every possible `ekind`. For a `__attribute__((packed))` unsigned enum (`ekind = IUChar`),
`get_ikind_str` produces `'d'` on `master` (same as `unsigned char`, see #2819 / !48) and
automatically produces `'C'` when combined with !48.

A merge request with this fix and a regression test (`plugins/e-acsl/tests/format/printf_enum.c`)
is ready.

The analysis and fix were prepared with LLM assistance; I reviewed them and ran the reproducer and
tests described above.
