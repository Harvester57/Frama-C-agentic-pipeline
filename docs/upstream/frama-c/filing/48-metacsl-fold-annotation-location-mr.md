## Problem

With `-meta-fold`, an instance is a call to the generated predicate. `create_call` builds it with
`Logic_const.papp` and no location, so it gets `Kernel.gen_loc`: the report and WP show the
assertion as "generated by Frama-C kernel", and E-ACSL reports its failure at `<unknown>:0`. The
same property unfolded keeps the location of the meta property. The fold oracle of
`meta-wp/typing.c` records it:

```
-Goal Assertion 'test,meta' (generated by Frama-C kernel):
+Goal Assertion 'test,meta' ("typing.c", line 22):
```

(the second line is what the default configuration's oracle has).

The wrappers around an instance have the same defect, folded or not: `post` (the implication from
the `assumes` of a callee's behavior) and `post_fold` (the `\forall` of `-meta-quantify-range`), in
`external_assigns` and `passthrough_from`, use `pimplies` and `pforall` without `~loc`.

## Change

- `create_call` takes `~loc`; `create_instance` passes the location of the instance it stands for
  (`inst.pred_loc`).
- `post` and `post_fold` give the implication and the `\forall` the location of the predicate they
  wrap, in the writing and the reading visitors.

Only locations change.

## Tests

Built on Frama-C 34.0~beta (Selenium) with one line removed from `meta_parse.ml` for the build only
(the `PLpointer_comparable` case, a constructor 34.0~beta does not have yet); that line is not part
of the patch.

- **Issue's reproducer.** Before: `- Assertion 'meta' (generated by Frama-C kernel)` in the report
  and `<unknown>:0: Error: Assertion failed:` from E-ACSL. After: `("fold.c", line 30)` and
  `fold.c:30: Error: Assertion failed:`; the unfolded property keeps line 35 in both.
- **Wrappers.** A target calling `/*@ assigns p[0 .. n-1]; */ void fill(int *p, int n);`, under
  `-meta-quantify-range` with and without `-meta-fold`; a target calling a function whose
  `assigns *p` sits in a behavior with `assumes n > 0`, with and without `-meta-fold`; a `\reading`
  property through `/*@ assigns \result \from p[0 .. n-1]; */` under `-meta-quantify-range`, with
  and without `-meta-fold`. E-ACSL's assertion data went from `file = "<unknown>"`, `line = 0` to
  the file and the line of the property in all six.
- **Suites.** `meta`, `meta-wp` and `meta-deduce`, default and fold configurations, on `master` and
  on `master` with the patch (same build setup): the result logs are identical except
  `meta-wp/result_fold/typing.0.res.log`, whose oracle the patch updates. The updated oracle is
  byte for byte the log of the patched build. SWI-Prolog is not installed on my setup, so the
  deduction checks of `meta-deduce` fail the same way in both builds and were not exercised.
- No new test: the updated `typing.c` oracle fails without the change and passes with it.
- Not run: `make lint` and the header check.

The change was prepared with LLM assistance (Claude Code); I reviewed it and ran the tests
described above.
