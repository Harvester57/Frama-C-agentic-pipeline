## Problem

With `-meta-fold`, an instance is a call to the generated predicate. `create_call` builds it with
`Logic_const.papp` and no location, so it gets `Kernel.gen_loc`: the report and WP show the
assertion as "generated by Frama-C kernel", and E-ACSL reports its failure at `<unknown>:0`. The
same property unfolded keeps the location of the meta property. The fold oracle of
`meta-wp/typing.c` records it:

```
-Goal Assertion 'test,meta' (generated by Frama-C kernel):
+Goal Assertion 'test,meta' ("typing.c", line 22):
```

(the second line is what the default configuration's oracle has).

The wrappers around an instance have the same defect, folded or not: `post` (the implication from
the `assumes` of a callee's behavior) and `post_fold` (the `\forall` of `-meta-quantify-range`), in
`external_assigns` and `passthrough_from`, use `pimplies` and `pforall` without `~loc`.

## Change

- `meta_annotate.ml`:
  - `create_call` takes `~loc`; `create_instance` passes the location of the instance it stands for
    (`inst.pred_loc`).
  - `post` and `post_fold` give the implication and the `\forall` the location of the predicate they
    wrap (`prop.pred_loc`), in the writing and the reading visitors.
- `CHANGELOG.md`: adds an entry under `# Version dev`.
- `tests/meta/fold_location.c` (with `oracle/fold_location.0.res.oracle` and
  `oracle_fold/fold_location.0.res.oracle`): new regression test using `-report` that exercises all
  three fixed paths — folded calls (`create_call`), callee behavior `assumes` (`post` in both
  `\writing` and `\reading`), and `-meta-quantify-range` (`post_fold` in both `\writing` and
  `\reading`) — in both the default and `fold` configurations.
- `tests/meta-wp/oracle_fold/typing.0.res.oracle`: updated so `Goal Assertion 'test,meta'` records
  `("typing.c", line 22)` instead of `(generated by Frama-C kernel)`.

Only locations change.

## Tests

Built on Frama-C 34.0~beta (Selenium) with one line removed from `meta_parse.ml` for the build only
(the `PLpointer_comparable` case, a constructor 34.0~beta does not have yet); that line is not part
of the patch.

- **Issue's reproducer.** Before (0.12~beta and unpatched `master`):
  `- Assertion 'meta' (generated by Frama-C kernel)` in `-report` and
  `<unknown>:0: Error: Assertion failed:` from E-ACSL. After: `("fold.c", line 30)` and
  `fold.c:30: Error: Assertion failed:`; the unfolded property keeps line 35 in both.
- **New regression test (`tests/meta/fold_location.c`).** Fails on unpatched `master`
  (`dune build @tests/meta/fold_location.diff` exits 1: 5 of 6 assertions in the default
  configuration — `direct_folded`, `write_assumes`, `read_assumes`, `write_range`, `read_range` —
  and all 6 of 6 in the `fold` configuration print `(generated by Frama-C kernel)` instead of their
  property line numbers). Passes with the patch in both configurations (all 6 assertions print their
  property lines: 37, 43, 48, 53, 58 and 63).
- **Wrappers under E-ACSL.** A target calling `/*@ assigns p[0 .. n-1]; */ void fill(int *p, int n);`,
  under `-meta-quantify-range` with and without `-meta-fold`; a target calling a function whose
  `assigns *p` sits in a behavior with `assumes n > 0`, with and without `-meta-fold`; a `\reading`
  property through `/*@ assigns \result \from p[0 .. n-1]; */` under `-meta-quantify-range`, with
  and without `-meta-fold`. E-ACSL's assertion data went from `file = "<unknown>"`, `line = 0` to
  the file and the line of the property in all six.
- **Suites.** `tests/meta` (22 tests per configuration, including `fold_location.c`) and
  `tests/meta-wp` (12 tests per configuration, including the updated
  `oracle_fold/typing.0.res.oracle`) run with `dune build @tests/meta/ptests @tests/meta-wp/ptests`
  in both the default and `fold` configurations: exit 0, zero regressions compared with unpatched
  `master` (all 21 + 21 + 12 + 12 existing tests are identical except `meta-wp/typing.c` in `fold`,
  whose oracle the patch updates).
- **Not run:** `meta-deduce` (SWI-Prolog is not installed on my setup), `make lint` and the header
  check.

described above.
