## Problem

On function entry, E-ACSL registers each tracked formal with `__e_acsl_store_block` but never marks
it initialized, although the caller has just written it. Every check that reads the shadow memory
of a formal then fails on every call: `\initialized(&s.f)` on a field of a struct passed by value
(user annotation as in #177, or RTE guard with initialization checks), and `\initialized(pk)` with
`pk = &k` for a scalar formal, even after `k = 7;`.

## Change

`plugins/e-acsl/src/code_generator/memory_observer.ml{,i}`: new `store_formals`, which emits
`__e_acsl_store_block` followed by `__e_acsl_full_init` for each tracked formal, as
`global_observer.ml` does for globals ("a global is both allocated and initialized").
`injector.ml` (`inject_in_stmt`) calls it instead of `store` for the formals. The rest of E-ACSL
already assumes formals are initialized (`add_initializer` and `needs_guard` skip whole formals).

Cost: an uninitialized member of a struct passed by value is no longer reported when the callee
reads it; today that check fails on correct calls too.

**Oracle churn (honest consequence of the fix).** 57 existing `gen_*.c` oracles of
`plugins/e-acsl/tests` change, each by `__e_acsl_full_init((void *)(& <formal>));` lines right after
a formal's `__e_acsl_store_block` (210 lines added, none removed or modified): `bts` 12, `memory`
13, `temporal` 8, `constructs` 6, `builtin` 4, `concurrency` 4, `special` 4, `libc` 3, `format` 2,
`inductive` 1. They were regenerated by running the ptests with the patch and promoting; no
`.res.oracle` and no `dev` oracle changes.

Regression test: `plugins/e-acsl/tests/bts/issue-framac-177.c` (`requires \initialized(&s.len)` and
`assert \initialized(&s.t)` on a by-value struct; `assert \initialized(pk)` on `&k` after `k = 7`),
with its default-configuration oracles. Its `dev` run (compile and execute) aborts on `master` and
passes with the patch.

## Testing

On `3dff90fc70` (Debian 13, OCaml 5.5 switch, gcc 14.2.0), with the patch built and installed:

| Check | `master` | Patched |
|---|---|---|
| `requires \initialized(&s.len)` on a fully initialized by-value struct, plain `e-acsl-gcc` | `Precondition failed: \initialized(&s.len)`, abort | exit 0 |
| `k = 7; int *pk = &k; return *pk * 2;`, `-F "-rte -rte-initialized @all"` | `E-ACSL RTE failed: \initialized(pk)`, abort | exit 0 |
| Uninitialized local read (`int x; if (c) x = 1; return x;`, `c == 0`), `-F "-rte -rte-initialized @all"` | reported | still reported |
| Uninitialized `int` passed by value | reported at the call | still reported at the call |

- ptests `plugins/e-acsl/tests`, default configuration: the 57 `gen_*.c` changes above plus the
  new test, promoted; rerun clean. `dev` configuration (every test compiled and run): passes. The
  same `dev` run on unpatched `3dff90fc70` passes as well (baseline).
- Together with the fix for `\result` fields (separate MR, `rte_analysis.ml`): both patches apply
  together on `3dff90fc70`, and both reproducers and the negative controls give the results above.
  With both applied, the ptests of `plugins/e-acsl/tests` with the oracles of the two MRs pass in
  the default and `dev` configurations with no difference: the two changes do not touch the same
  oracle.
- `./dev/check-files.sh -p` (that is, `make check-lint` and `make check-headers` on the changed
  files) with ocp-indent 1.10.0 and clang-format 19.1.7: clean. The first commit's new test was not
  clang-formatted; the second commit formats it, and its two oracles follow the new line numbers
  (the default configuration of `bts/` rerun after it passes).
- `git diff --check`: clean except a trailing space in the new `.res.oracle` (`Warning: ` line)
  and the blank line at the end of the new `gen_*.c`, as in every E-ACSL oracle.
