## Problem

On function entry, E-ACSL registers each tracked formal with `__e_acsl_store_block` but never marks
it initialized, although the caller has just written it. Every check that reads the shadow memory
of a formal then fails on every call: `\initialized(&s.f)` on a field of a struct passed by value
(user annotation as in #177, or RTE guard with initialization checks), `\initialized(pk)` with
`pk = &k` for a scalar formal (even after `k = 7;`), and `\initialized(p)` / `\initialized(q)` for
`main`'s `argc` and `argv` (because `injector.ml` skips `main` and delegates tracking to
`argv_alloca`, which allocated `argc_ref` and `argv_ref` without marking them initialized in either
observation model).

## Change

- `plugins/e-acsl/src/code_generator/memory_observer.ml{,i}`: new `store_formals`, which emits
  `__e_acsl_store_block` followed by `__e_acsl_full_init` for each tracked formal, as
  `global_observer.ml` does for globals ("a global is both allocated and initialized").
  `injector.ml` (`inject_in_stmt`) calls it instead of `store` for the formals. The rest of E-ACSL
  already assumes formals are initialized (`add_initializer` and `needs_guard` skip whole formals).
- `plugins/e-acsl/share/e-acsl/observation_model/segment_model/e_acsl_segment_observation_model.c`:
  in `argv_alloca`, call `initialize_static_region((uintptr_t)argc_ref, sizeof(int))` and
  `initialize_static_region((uintptr_t)argv_ref, sizeof(char **))` right after `shadow_alloca`,
  matching the initialization of `argv`, `*argv`, and `*environ` immediately below.
- `plugins/e-acsl/share/e-acsl/observation_model/bittree_model/e_acsl_bittree_observation_model.c`:
  in `argv_alloca`, call `eacsl_initialize((void *)argc_ref, sizeof(int))` and
  `eacsl_initialize((void *)argv_ref, sizeof(char **))` right after `eacsl_store_block`, matching
  the initialization of `argv`, `*argv`, and `*environ` immediately below.

Cost: an uninitialized member of a struct passed by value is no longer reported when the callee
reads it; today that check fails on correct calls too.

**Oracle churn (honest consequence of the fix).** 57 existing `gen_*.c` oracles of
`plugins/e-acsl/tests` change on `b80fcac74f`, each by `__e_acsl_full_init((void *)(& <formal>));`
lines right after a formal's `__e_acsl_store_block` (210 lines added, none removed or modified):
`memory` 13, `bts` 12, `temporal` 8, `constructs` 6, `builtin` 4, `concurrency` 4, `special` 4,
`libc` 3, `format` 2, `inductive` 1. They were regenerated by running the ptests with the patch and
promoting; no `.res.oracle` and no `dev` oracle changes.

Regression test: `plugins/e-acsl/tests/bts/issue-framac-177.c` (`requires \initialized(&s.len)` and
`assert \initialized(&s.t)` on a by-value struct; `assert \initialized(pk)` on `&k` after `k = 7`;
and `assert \initialized(p)` / `assert \initialized(q)` on `&argc` / `&argv` in `main`), formatted
with `clang-format` 19.1.7, with its default-configuration oracles. Both its default and `dev`
(compile and execute) runs fail on `master` and pass with the patch.

## Testing

On `master` `b80fcac74f` (Debian 13, OCaml 5.5 switch, gcc 14.2.0), validated in a fresh container
as a single squashed commit (65 files changed, 517 insertions, 1 deletion):

| Check | `master` (`b80fcac74f`) | Patched |
|---|---|---|
| `requires \initialized(&s.len)` on a fully initialized by-value struct, plain `e-acsl-gcc` | `Precondition failed: \initialized(&s.len)`, exit 134 | exit 0 |
| `k = 7; int *pk = &k; return *pk * 2;`, `-F "-rte -rte-initialized @all"` | `E-ACSL RTE failed: \initialized(pk)`, exit 134 | exit 0 |
| `main(int argc, char **argv)` with `int *p = &argc; char ***q = &argv; assert \initialized(p); assert \initialized(q);` (segment model) | `Assertion failed: \initialized(p)`, exit 134 | exit 0 |
| Same `main(int argc, char **argv)` test with `-m bittree` | `Assertion failed: \initialized(p)`, exit 134 | exit 0 |
| Uninitialized local read (`int x; if (c) x = 1; return x;`, `c == 0`), `-F "-rte -rte-initialized @all"` | reported | still reported |
| Uninitialized `int` passed by value | reported at the call | still reported at the call |

- `plugins/e-acsl/tests/bts/issue-framac-177.c`: fails on `master` in both default (missing
  `__e_acsl_full_init` on formals) and `dev` (aborts at runtime), passes in both default and `dev`
  with the patch (`exit=0`).
- Full `plugins/e-acsl` default test suite: passes cleanly (`exit=0`) with the 57 promoted
  `gen_*.c` oracles and the new test.
- `./dev/check-files.sh -p HEAD~1` (`make check-lint` and `make check-headers` on all 65 changed
  files) with ocp-indent and clang-format 19.1.7: clean (`exit=0`), no mode changes or executable
  new files.
- `git diff --check`: clean except the standard trailing space in `Warning: ` lines of the new
  `.res.oracle` and the blank line at the end of the new `gen_*.c`, as in every E-ACSL oracle.
- Note on bittree model for non-`main` formals: `main`'s `argc`/`argv` pass standalone under
  `-m bittree` because `argv_alloca` uses `eacsl_initialize` (which calls `bt_find`); non-`main`
  formals rely on `__e_acsl_full_init` (which calls `bt_lookup` / `pt_lookup`), so testing
  `f_struct`/`f_scalar` under `-m bittree` also depends on the separate `pt_lookup` fix.
