# [Kernel] ACSL wide-string parser `wcharlist_of_string` treats `8` and `9` as octal digits and does not recognize `\v`

<!-- Everything below this line is the issue description. -->

### Summary

In `Logic_typing.wcharlist_of_string`, octal escape sequences inside ACSL wide string literals
match `'0'..'9'` instead of `'0'..'7'`, so digits `'8'` and `'9'` immediately following an octal
escape are consumed as octal digits (for instance, `L"\18"` is parsed as the single wide character
`1 * 8 + 8 = 16` instead of `'\1'` followed by `'8'`). In the same function, the standard C escape
`\v` (vertical tab, `11`) is missing, emitting an `Ill-formed escape sequence in wide string`
warning and storing `'v'` (`118`) instead.

### Steps to reproduce the issue

`wstring_escapes.c`:

```c
int main(void) {
  //@ check oct_18: L"\18"[0] == 1 && L"\18"[1] == '8';
  //@ check oct_79: L"\79"[0] == 7 && L"\79"[1] == '9';
  //@ check oct_123: L"\123"[0] == 83;
  //@ check esc_v: L"\v"[0] == 11;
  return 0;
}
```

```sh
frama-c -print wstring_escapes.c
```

### Expected behaviour

Per ISO C11 6.4.4.4 (octal-digit is `0` through `7`; `\v` is a simple escape sequence for vertical
tab `11`), `L"\18"` consists of `[1, '8']`, `L"\79"` consists of `[7, '9']`, and `L"\v"` consists
of `[11]` with no warning.

### Actual behaviour

```text
[kernel] Parsing wstring_escapes.c (with preprocessing)
[kernel] wstring_escapes.c:5: Warning: Ill-formed escape sequence in wide string
/* Generated by Frama-C */
int main(void)
{
  int __retres;
  /*@
  check
    oct_18:
      (\let tmp = L"\\020" ; tmp[0]) ≡ 1 ∧
      (\let tmp = L"\\020" ; tmp[1]) ≡ '8';
   */
  ;
  /*@
  check
    oct_79:
      (\let tmp = L"A" ; tmp[0]) ≡ 7 ∧ (\let tmp = L"A" ; tmp[1]) ≡ '9';
   */
  ;
  /*@ check oct_123: (\let tmp = L"S" ; tmp[0]) ≡ 83; */ ;
  /*@ check esc_v: (\let tmp = L"v" ; tmp[0]) ≡ 11; */ ;
  __retres = 0;
  return __retres;
}
```

`L"\18"` became `L"\\020"` (`16`), `L"\79"` became `L"A"` (`7 * 8 + 9 = 65`), and `L"\v"` warned
and became `L"v"` (`118`).

- Frama-C version: 35.0~~dev (Bromine), `master` at 189053d4a2; also 34.0~beta (Selenium), same output

### Additional information (optional)

**Cause.** In `src/kernel/services/ast_queries/logic_typing.ml`:

- Lines 30 and 62 (`wcharlist_of_string`) match `x when '0' <= x && x <= '9'` instead of
  `x when '0' <= x && x <= '7'`.
- Lines 65-75 (`treat_escape_sequence`) handle `\a`, `\b`, `\f`, `\n`, `\r`, `\t`, `\'`, `\"`,
  `\?`, and `\\`, omitting `\v` (which `clexer.mll:275` and `logic_lexer.mll:562` both support).

**Fix.** Change `'9'` to `'7'` at `logic_typing.ml:30` and `:62`, and add
`| 'v' -> incr i; res:= Int64.of_int 11 :: !res` at line 71. A merge request with this fix and a
regression test (`tests/spec/wstring_escapes.c`) is ready.

The analysis and fix were prepared with LLM assistance; I reviewed them and ran the reproducer and
tests described above.
