# [Eva] `numerors` domain: decimal-only literal parser drops a sure alarm on `DBL_MAX` and crashes on `FLT_MAX`, `INFINITY`, `0x1.ep0`, and `1.5d`

<!-- Everything below this line is the issue description. -->

### Summary

The Eva `numerors` domain (`-eva-domains numerors`) parses floating-point constant source text with
`Rational.of_string` (`src/lib/arithmetic/rational.ml`), which only splits decimal numbers on `'e'`
and only strips `f`/`l`/`f32`/`f64` suffixes. In addition, `IEEE754.Make.constant`
(`plugins/eva/src/values/non_integer_arithmetic/IEEE754.ml`) passes non-finite `CReal` source text
directly to `Scalar.of_string`. This causes:

1. **Silent loss of a sure out-of-bounds alarm** on standard `<float.h>` `DBL_MAX`
   (`0x1.fffffffffffffp+1023` is misparsed as `8.096e+304`, making a live comparison `x < DBL_MAX`
   dead);
2. **Wrong real intervals** on hexadecimal floating-point literals without digit `e` (e.g.
   `0x1.8p1` is parsed as `0.048` instead of `3.0`);
3. **Uncaught OCaml exceptions (exit status 125)** on `<float.h>` `FLT_MAX` and `0x1.ep0`
   (`Failure("int_of_string")`), and on GCC `d`-suffixed literals (`1.5d` under `-machdep gcc_x86_64`)
   as well as `<math.h>` `INFINITY`, `NAN`, and `HUGE_VAL`
   (`Invalid_argument("Z.of_substring_base: invalid digit")`).

### Steps to reproduce the issue

Lost sure alarm (`alarm.c`):

```c
#include <float.h>
#include "__fc_builtin.h"

int t[2];

int main(void) {
  double x = Frama_C_double_interval(1e305, 1e306);
  double m = DBL_MAX;
  int i = 0;
  if (x < m)
    i = 2;
  t[i] = 1;
  return i;
}
```

```sh
frama-c -eva alarm.c
frama-c -eva -eva-domains numerors alarm.c
```

Wrong real interval (`hex.c`):

```c
#include "__fc_builtin.h"

void main(void) {
  double x = Frama_C_double_interval(1.0, 2.0);
  double h = x * 0x1.8p1;
  double d = x * 3.0;
  Frama_C_domain_show_each_hex(h);
  Frama_C_domain_show_each_dec(d);
}
```

```sh
frama-c -eva -eva-domains numerors -eva-msg-key=d-numerors hex.c
```

Crash reproducers (`crash_hex.c`, `crash_fltmax.c`, `crash_d.c`, `crash_inf.c`):

```c
/* crash_hex.c */

  double z = 0x1.ep0;

}
```

```c
/* crash_fltmax.c */

int main(void) {

}
```

```c
/* crash_d.c */

}
```

```c
/* crash_inf.c */
```


### Expected behaviour

- On `alarm.c`, `-eva -eva-domains numerors` preserves the sure out-of-bounds alarm
  `accessing out of bounds index. assert i < 2;` just like plain `-eva`.
- On `hex.c`, `h` and `d` both have `numerors: Real : [3. .. 6.]`.
- On `crash_hex.c`, `crash_fltmax.c`, and `crash_d.c`, Eva finishes with exit status 0 and exact
  `numerors` values (`1.875`, `FLT_MAX`, `1.5`).
- On `crash_inf.c`, Eva finishes with exit status 0 and emits the expected `is_nan_or_infinite`
  alarm instead of crashing.

### Additional information (optional)

**Cause.**

1. `Rational.of_string` (`src/lib/arithmetic/rational.ml`, lines 33-62 on `189053d4a2`) splits on
   `'e'` (`split_significant_exponent`) and on `'.'` (`significant_of_string`, dividing by
   `10^(String.length fractional)`). On hexadecimal floating-point literals without `'e'`, it
   concatenates the `p` exponent into the fractional part and divides by a power of 10
   (`0x1.8p1` -> `0x18p1 / 1000 = 0.048`; `DBL_MAX = 0x1.fffffffffffffp+1023` -> `8.096e+304`); on
   literals containing hex digit `'e'` (`0x1.ep0`, `FLT_MAX`), `int_of_string` fails on the rest of
   the string. `remove_float_suffix` also omits `'d'`/`'D'`.
2. `IEEE754.Make.constant` (`plugins/eva/src/values/non_integer_arithmetic/IEEE754.ml`, lines
   567-583) ignores the `float` value in `CReal (_, fkind, Some str)` and calls `Scalar.of_string str`
   unconditionally even when the constant is non-finite (`INFINITY`, `NAN`, `HUGE_VAL`), and also
   does not guard `CReal (f, fkind, None)` for non-finite folded values.

**Fix.**

- In `src/lib/arithmetic/rational.ml`, strip C floating-point suffixes (`f`/`d`/`l`/`f32`/`f64`,
  without stripping trailing hex digits from integer literals) and delegate parsing to Zarith's
  `Q.of_string`, which handles decimal, scientific, hexadecimal-float (`0x...p...`), and rational
  notations natively.
- In `plugins/eva/src/values/non_integer_arithmetic/IEEE754.ml`, return `Top` in `Make.constant`
  whenever `not (Float.is_finite f)`.

Related to #2831 (same literal-parsing family in WP). A merge request with this fix and a regression
test (`plugins/eva/tests/numerors/float_literals.c`) is ready.

The analysis and fix were prepared with LLM assistance; I reviewed them and ran the reproducer and
tests described above.
