# [Libc] `sigaction` assigns `*oldact` from `&__fc_sigaction` and omits `\old` in `oldact_assigned`

<!-- Everything below this line is the issue description. -->

### Summary

In Frama-C's libc `share/libc/signal.h`, the contract of `sigaction` has two defects affecting
`oldact`: it assigns `*oldact` `\from &__fc_sigaction` (the address of the array rather than the
entry `__fc_sigaction[signum]`), and its postcondition `oldact_assigned` checks
`\subset({*oldact}, __fc_sigaction[signum])` in the post-state instead of
`\old(__fc_sigaction[signum])`. In Eva, installing any non-null signal handler while saving the
previous action triggers `[eva:ensures-false]` and stops the analysis (`NON TERMINATING FUNCTION`),
and querying a previously installed handler with `act == NULL` makes `old.sa_handler == h1`
evaluate to `invalid`.

### Steps to reproduce the issue

`repro.c`:

```c
#include <signal.h>

void h1(int s) { (void)s; }
void h2(int s) { (void)s; }

int main(void) {
  struct sigaction a = {0}, b = {0}, old = {0};
  a.sa_handler = h1;
  b.sa_handler = h2;
  sigaction(SIGINT, &a, 0);
  sigaction(SIGINT, &b, &old);
  //@ assert old_is_h1: old.sa_handler == h1;
  return 0;
}
```

```sh
frama-c -eva repro.c
```

A single call with a non-null handler (`b.sa_handler = h1; sigaction(SIGINT, &b, &old);`) also
stops with `[eva:ensures-false]` and `NON TERMINATING FUNCTION`. Querying after install
(`sigaction(SIGINT, &a, 0); sigaction(SIGINT, 0, &old); //@ assert old.sa_handler == h1;`) marks
the assertion `invalid (stopping propagation)`.

### Expected behaviour

`sigaction` copies the previous action from `__fc_sigaction[signum]` into `*oldact` (per POSIX
`sigaction`), does not emit `[eva:ensures-false]` or `[eva:garbled-mix:assigns]` for `*oldact`,
reaches all statements of `main`, and keeps `old.sa_handler == h1` reachable.

### Additional information (optional)

**Cause.** `share/libc/signal.h:247-253` on `189053d4a2`:

```c
  assigns *oldact \from &__fc_sigaction;
  assigns __fc_sigaction[signum] \from *act;
  ...
  ensures oldact_assigned: oldact == \null ||
                           \subset({*oldact}, __fc_sigaction[signum]);
```

1. Line 247 writes `\from &__fc_sigaction` (the array's address) instead of
   `__fc_sigaction[signum]`, so Eva populates `*oldact` with a garbled mix of `&__fc_sigaction`
   (also visible in `tests/libc/oracle/signal_c_h.0.res.oracle:136`).
2. Line 253 evaluates `__fc_sigaction[signum]` in the post-state (after `*act` has been installed)
   instead of `\old(__fc_sigaction[signum])`. Whenever `*act` contains a non-null handler pointer,
   the garbled mix of `&__fc_sigaction` and the post-state handler have empty intersection, so
   `oldact_assigned` evaluates to false and Eva terminates analysis at the call.

**Fix.** Change line 247 to `assigns *oldact \from __fc_sigaction[signum], indirect:signum;` and
line 253 to `\subset({*oldact}, \old(__fc_sigaction[signum]));`. A merge request with a new test
and updated `signal_c_h` oracles follows.

The analysis and fix were prepared with LLM assistance (Antigravity / Gemini); I reviewed them and
ran the reproducer and tests described above.
