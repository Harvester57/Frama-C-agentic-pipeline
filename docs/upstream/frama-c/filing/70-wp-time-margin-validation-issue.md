# [WP] `-wp-time-margin` is unchecked (crashes with `Failure("float_of_string")` after provers run, accepts `nan`/`inf`) and manual states wrong default (`5s` vs `0.5`)

<!-- Everything below this line is the issue description. -->

### Summary

`-wp-time-margin` is declared as a `String` parameter (`plugins/wp/src/wp_parameters.ml:846-857`) and parsed lazily with an unguarded `float_of_string` in `VCS.time_fits` (`VCS.ml:132`) and `ProofEngine.has_result` (`ProofEngine.ml:598`).

- Passing an invalid value such as `-wp-time-margin 1s` (invited directly by the WP manual, which says `Default is 5s.`) is accepted at CLI parsing, runs all provers, and then crashes with `Unexpected error (Failure("float_of_string"))` (exit code 125) before printing the `Proved goals` summary.
- Non-finite or negative values (`nan`, `inf`, `-1`) are accepted silently.
- The WP manual (`plugins/wp/doc/manual/wp_plugin.tex:1441`) states `Default is 5s.`, whereas the code defaults to `0.5` seconds (`wp_parameters.ml:849`). (Line 1435 similarly says `Default is 5s.` for `-wp-time-extra`, whose code default is `1`.)

### Steps to reproduce the issue

`margin.c`:

```c
/*@ requires 0 <= x && x < 100;
    ensures \result == x * x && \result >= 0; */
int sq(int x) {
  return x * x;
}
```

```sh
OCAMLRUNPARAM=b frama-c -debug 1 -wp -wp-timeout 5 -wp-time-margin 1s margin.c
frama-c -wp -wp-timeout 5 -wp-time-margin nan margin.c
```

### Expected behaviour

Invalid values (`1s`, `abc`), non-finite values (`nan`, `inf`), and negative values (`-1`) should be rejected at command-line parsing time with a clean `User Error` (exit code 1) before running provers, and the WP manual should document the actual default (`0.5` seconds).

### Actual behaviour

`-wp-time-margin 1s` runs Alt-Ergo and then crashes with exit code 125:

```text
[kernel] Parsing margin.c (with preprocessing)
[wp] Running WP plugin...
[wp] Warning: Missing RTE guards
[wp] 1 goal scheduled

  Please report as 'crash' at https://git.frama-c.com/pub/frama-c/issues

```

`-wp-time-margin nan` exits 0 silently without any error or warning.

### Additional information (optional)

**Cause.** On `189053d4a2`:

- `plugins/wp/src/wp_parameters.ml:846-857` (and `wp_parameters.mli:116`) define `TimeMargin` as `Parameter_sig.String` with `default = "0.5"` instead of `Parameter_sig.Float`.
- `plugins/wp/src/VCS.ml:132` and `plugins/wp/src/ProofEngine.ml:598` (the only two callers in the repository) call `float_of_string @@ Wp_parameters.TimeMargin.get ()` without exception handling.
- `plugins/wp/doc/manual/wp_plugin.tex:1441` documents `Default is \verb+5s+.`.

**Fix.** Change `TimeMargin` from `String` to `Float` (`default = 0.5`), set `TimeMargin.set_range ~min:0.0 ~max:infinity` with an `add_set_hook` rejecting non-finite values (`not (Stdlib.Float.is_finite f)`, because `Parameter_builder.Float`'s `f < min`/`f > max` comparisons do not reject `nan`), drop `float_of_string` in `VCS.ml` and `ProofEngine.ml`, and update `wp_plugin.tex:1441` to `0.5` seconds. A merge request follows.

The analysis and fix were prepared with LLM assistance; I reviewed them and ran the reproducer and tests described above.
