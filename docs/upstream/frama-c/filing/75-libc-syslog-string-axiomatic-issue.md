# [Libc] `syslog` loses all string preconditions when only `<syslog.h>` is included

<!-- Everything below this line is the issue description. -->

### Summary

When a C translation unit includes `<syslog.h>` without also including `<stdio.h>`, `<string.h>`,
or another header that brings in `__fc_string_axiomatic.h`, Frama-C's Variadic translation cannot
locate the ACSL predicates `valid_read_string` / `valid_read_nstring`, emits a
`kernel:libc:frama-c` warning, and silently drops all string-validity preconditions from the
generated `syslog_va_*` specification. As a result, Eva reports zero alarms when a non-NUL-terminated
buffer is passed to `syslog(LOG_ERR, "%s", buf)`.

### Steps to reproduce the issue

`repro.c`:

```c
#include <syslog.h>

int main(void) {
  char buf[2] = {'a', 'b'}; /* not NUL-terminated */
  syslog(LOG_ERR, "%s", buf);
  return 0;
}
```

```sh
frama-c -eva repro.c
```

### Expected behaviour

No `Unable to locate ACSL predicate` warning is emitted. Variadic generates
`requires valid_read_string(param1);` and `requires valid_read_string(param2);` on `syslog_va_1`
(matching the behaviour when `#include <stdio.h>` is also present), and Eva flags the invalid
precondition on `buf`.

### Contextual information

### Additional information (optional)

**Cause.** `src/kernel/services/ast_transformations/variadic/classify.ml:137` classifies `syslog`
as `PrintfLike`, and `standard.ml:408-416, 445-449, 523-542` looks up `valid_read_string`,
`valid_read_nstring`, `valid_read_wstring`, and `valid_read_nwstring` in `Logic_env`, skipping each
precondition on `Not_found`. Unlike 20 other POSIX/ISO headers in `share/libc/` (`stdio.h`,
`string.h`, `pwd.h`, `fcntl.h`, `unistd.h`, `wchar.h`, `err.h`, `netdb.h`, etc.),
`share/libc/syslog.h:11-15` does not include `"__fc_string_axiomatic.h"`. POSIX `<syslog.h>` does
not require `<stdio.h>` or `<string.h>` to call `syslog`.

**Fix.** Add `#include "__fc_string_axiomatic.h"` to `share/libc/syslog.h`. A merge request with
a regression test covering both `%s` (`valid_read_string`) and `%.5s` (`valid_read_nstring`)
follows.

The analysis and fix were prepared with LLM assistance (Antigravity / Gemini); I reviewed them and
ran the reproducer and tests described above.
