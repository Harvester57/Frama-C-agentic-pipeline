# [Kernel] Unbalanced quote or C23 digit separator (1'000) in ACSL annotation aborts logic preprocessing with Kernel.fatal

<!-- Everything below this line is the issue description. -->

### Summary

When an ACSL annotation contains an unbalanced double or single quote (such as `//@ check o5: "abc == 1;`
or `//@ check ch: 'a == 1;`) or a C23 digit separator (such as `//@ check c23: 1'000 == 1000;`),
`Logic_preprocess` first reports a user error (`Can't preprocess annotation: eof while parsing a
string/char literal / Some annotations will be kept as is`) and then immediately aborts Frama-C with
an internal error (`Kernel.fatal`: `too few annotations in result file while preprocessing
annotations`, exit code 4).

### Steps to reproduce the issue

`unbalanced_str.c`:

```c
void f(void) {
  //@ check o5: "abc == 1;
}
```

```sh
frama-c -no-autoload-plugins unbalanced_str.c
```

Or with a C23 digit separator (`c23_sep.c`):

```c
void f(void) {
  //@ check c23: 1'000 == 1000;
}
```

```sh
frama-c -no-autoload-plugins c23_sep.c
```

### Expected behaviour

Frama-C should report the user error cleanly (exit code 1) without hitting `Kernel.fatal` /
`internal error` (`too few annotations in result file while preprocessing annotations`).

### Actual behaviour

Both files abort with exit code 4 and an internal error (`Kernel.fatal`):

```text
[kernel] Parsing unbalanced_str.c (with preprocessing)
```

### Additional information (optional)

**Cause.** In `src/kernel/internals/parsing/logic_preprocess.mll`:

1. When `main` sees `//@` or `/*@`, `process_annot_start` (lines 185-191) appends an
   `annot_content` placeholder to `output_buffer` and an `annot_beg` marker to `preprocess_buffer`.
2. When `char` (lines 426-444) or `string` (lines 446-461) encounters an unbalanced quote, it scans
   past `\n` to `eof` and calls `abort_preprocess` (lines 90-96), which logs a non-fatal
   `Kernel.error` and returns `()` without writing an `annot_end` marker.
3. `file` (line 531) then unconditionally invokes `preprocess_annots`, which calls `output_result`
   -> `next_preprocessed` (lines 120-127). Because `preprocess_buffer` has an unclosed `annot_beg`
   with no matching `annot_end`, `get_annot` reaches `End_of_file` and aborts with
   `Kernel.fatal "too few annotations in result file while preprocessing annotations"`.

**Fix.** Track `in_annot` and `aborted` flags in `logic_preprocess.mll` (reset in `reset ()`):

- In `abort_preprocess`, set `aborted := true`, close any open annotation with `annot_end` when
  `!in_annot` is true, and strip surrounding double quotes from `!curr_file` before passing it to
  `Filepath.of_string`.
- Add an `eof` arm to `annot`.
- In `preprocess_annots`, skip running `cpp` and use `ppname` directly when `!aborted` is true,
  keeping annotations as is without hitting `End_of_file` / `Kernel.fatal`.

Frama-C then aborts cleanly with exit code 1 (`invalid user input`) and zero internal errors. A
merge request with this fix and a regression test (`tests/spec/pp_unbalanced_quote.c`) is ready.

The analysis and fix were prepared with LLM assistance; I reviewed them and ran the reproducer and
tests described above.
