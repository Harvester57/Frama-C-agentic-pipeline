# [Kernel] Logic_utils.constFoldBinOpToInt crashes with Division_by_zero on loop unroll/unfold with 1/0

<!-- Everything below this line is the issue description. -->

### Summary

An ACSL `loop unroll` or `loop unfold` annotation whose constant expression contains an integer
division by zero (such as `/*@ loop unroll 1 / 0; */` or `/*@ loop unfold 0 / 0; */`) crashes
Frama-C with an uncaught `Division_by_zero` exception in `Logic_utils.constFoldBinOpToInt` instead
of returning `None` and emitting the usual warning.

### Steps to reproduce the issue

`unroll_div_zero.i`:

```c
void main(void) {
  int s = 0;
  /*@ loop unroll 1 / 0; */
  for (int i = 0; i < 3; i++) {
    s += i;
  }
  /*@ loop unfold 0 / 0; */
  for (int j = 0; j < 2; j++) {
    s += j;
  }
}
```

```sh
frama-c -eva unroll_div_zero.i
frama-c -ulevel-force -print unroll_div_zero.i
```

### Expected behaviour

`Logic_utils.constFoldBinOpToInt` should return `None` when the divisor is zero (just as it already
does for `Mod`), so Frama-C emits warnings for the non-constant/unsafe unroll/unfold directives and
exits 0 without crashing.

### Actual behaviour

Both commands abort with exit code 125 and an uncaught `Division_by_zero` exception:

```text
[kernel] Parsing unroll_div_zero.i (no preprocessing)
[kernel] Unexpected error (Division_by_zero).
  Please report as 'crash' at https://git.frama-c.com/pub/frama-c/issues
  Your Frama-C version is 35.0~~dev (Bromine).
```

### Additional information (optional)

**Cause.** In `src/kernel/services/ast_queries/logic_utils.ml`, `constFoldBinOpToInt` (lines
2385-2387) writes:

```ocaml
| Div ->
  if Z.(equal zero i2) && Z.(is_zero (erem i1 i2)) then None
  else Some (Z.ediv i1 i2)
```

When `i2` is zero, `Z.(equal zero i2)` evaluates to `true`, so `&&` immediately evaluates the
right-hand operand `Z.erem i1 i2`, raising `Division_by_zero`. When `i2` is non-zero, `&&`
short-circuits to `false` and `Some (Z.ediv i1 i2)` is always returned regardless of the remainder.

**Fix.** Change the `Div` branch to match `Mod` on the next line:

```ocaml
| Div -> if Z.(equal zero i2) then None else Some (Z.ediv i1 i2)
```

A merge request with this fix and a regression test (`tests/misc/unroll_div_zero.i`) is ready.
