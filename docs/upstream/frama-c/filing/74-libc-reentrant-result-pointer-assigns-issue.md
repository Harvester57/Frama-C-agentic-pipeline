# [Libc] `getpwnam_r`/`getpwuid_r` and `getut*_r` assign `*result`/`*ubufp` from `&__fc_*` instead of caller struct pointer

<!-- Everything below this line is the issue description. -->

### Summary

In Frama-C's libc, the reentrant lookup functions `getpwnam_r` and `getpwuid_r`
(`share/libc/pwd.h`) and `getutent_r`, `getutid_r`, and `getutline_r` (`share/libc/utmp.h`) assign
their output pointer parameter (`*result` / `*ubufp`) `\from &__fc_pwd` / `\from &__fc_utmp`
instead of the caller-supplied struct pointer (`pwd` / `ubuf`). In Eva, intersecting `*result`
with `ensures *result == \null || *result == pwd` eliminates `pwd` and leaves `*result == {0}`,
making every success branch dead code. In `<utmp.h>`, `*ubufp` becomes a garbled mix of
`&__fc_utmp`, producing spurious alignment/pointer-comparison alarms and making `res == &ub` dead.

### Steps to reproduce the issue

`repro.c`:

```c
#include <pwd.h>

int main(void) {
  struct passwd pw, *res1 = 0, *res2 = 0;
  char buf[256];
  int r1 = getpwnam_r("root", &pw, buf, sizeof(buf), &res1);
  if (r1 == 0 && res1 != 0) {
    //@ assert found_nam: res1 == &pw;
  }
  int r2 = getpwuid_r(0, &pw, buf, sizeof(buf), &res2);
  if (r2 == 0 && res2 != 0) {
    //@ assert found_uid: res2 == &pw;
  }
  return 0;
}
```

`repro_utmp.c`:

```c
#include <utmp.h>

int main(void) {
  struct utmp ub, *res = 0;
  int r = getutent_r(&ub, &res);
  if (r == 0 && res == &ub) {
    //@ assert utmp_reached: \true;
  }
  return 0;
}
```

```sh
frama-c -eva repro.c
frama-c -eva repro_utmp.c
```

### Expected behaviour

Per POSIX `getpwnam_r`/`getpwuid_r` and glibc `getutent_r`/`getutid_r`/`getutline_r`, on success
`*result` is set to `pwd` and `*ubufp` is set to `ubuf` (and to `NULL` on failure or not-found).
Eva should compute `res1 ∈ {{ NULL ; &pw }}`, `res2 ∈ {{ NULL ; &pw }}`, and
`res ∈ {{ NULL ; &ub }}` with zero pointer alarms, reaching and validating all success-branch
assertions (`found_nam`, `found_uid`, `utmp_reached`).

### Additional information (optional)

**Cause.**

- `share/libc/pwd.h:68,85` (`getpwnam_r`, `getpwuid_r`): `assigns *pwd, *result \from &__fc_pwd;`.
  Because `*result` has no dependency on `pwd`, Eva produces a garbled mix of `&__fc_pwd`, and
  reducing by `ensures *result == \null || *result == pwd` leaves only `{0}`. (`*pwd` also
  referenced the address `&__fc_pwd` instead of `__fc_pwd` and `buf`.)
- `share/libc/utmp.h:124,131,139` (`getutent_r`, `getutid_r`, `getutline_r`):
  `assigns *ubufp \from &__fc_utmp;` (and `indirect:*ut, &__fc_utmp` on `getutid_r`/`getutline_r`)
  with no dependency on `ubuf` and no postcondition constraining `*ubufp`.

Compare `share/libc/grp.h:46,57` (`getgrgid_r`, `getgrnam_r`: `assigns *result \from grp;`) and
`share/libc/dirent.h:90` (`readdir_r`: `assigns *result \from entry;`), which already model this
pattern correctly. All other `*_r` functions in `share/libc/` were checked and do not have this
defect.

**Fix.**

- In `share/libc/pwd.h` lines 68 and 85, split into:
  `assigns *pwd \from __fc_pwd, buf, indirect:buflen;` and
  `assigns *result \from pwd, indirect:__fc_pwd;`.
- In `share/libc/utmp.h` lines 124, 131, and 139, change `assigns *ubufp` to depend on `ubuf`
  (plus `indirect:*ut` on `getutid_r`/`getutline_r`) and add
  `ensures result_null_or_ubuf: *ubufp == \null || *ubufp == ubuf;`.

A merge request with a regression test covering all five functions follows.
