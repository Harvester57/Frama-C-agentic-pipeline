# [E-ACSL] Internal error `typing was not performed` on quantifiers with unsupported guards and on binary operations / libc contracts (`stpncpy`, `strlcat`)

<!-- Everything below this line is the issue description. -->

### Summary

E-ACSL aborts with an internal error (`Failure: typing was not performed on construct 0` or `1`, exit
status 4) whenever an unsupported subterm raises `Error.Not_yet` during `Typing` inside a composite
construct that short-circuits before typing its remaining children:

- **Quantifiers (`Pforall`/`Pexists`):** an unsupported logic function in a bound (such as
  `undef_fn(x) <= i < 3 ==> i >= 0`, or `strlen(src)` in Frama-C's `stpncpy` contract) aborts
  `type_bound_variables` before typing the quantifier goal. During translation,
  `Loops.mk_nested_loops` translates the goal first (or `Translate_ats.for_stmt` pre-translates an
  `\old(...)` parameter inside the goal), hitting an untyped constant.
- **Binary operations (`TBinOp`) and other composite constructs:** an unsupported first operand
  (such as `strlen(dest)` in Frama-C's `strlcat` contract `ensures \result == strlen(dest) + strlen(src);`
  or any `f(a) + f(b)` where `f` has a `reads` clause) aborts `type_term` before typing the second
  operand. `Labels.preprocess` still registers `\old(src)` / `\old(b)` for `Translate_ats.for_stmt`,
  which then translates its `\aligned(..., 1)` RTE guard and crashes on the untyped constant `1`.

This defect is distinct from #2806 (!37): even with !37 applied, all reproducers below still abort
with the exact same internal error.

### Steps to reproduce the issue

Quantifier path (`quant.c`):

```c
/*@ logic integer undef_fn(int x); */
int main(void) {
  int x = 0;
  /*@ assert \forall integer i; undef_fn(x) <= i < 3 ==> i >= 0; */
  return 0;
}
```

Binary-operation / `\old` RTE guard path without libc (`binop.c`):

```c
/*@ logic integer f(char *p) reads *p; */
/*@ ensures \result == f(a) + f(b); */
int g(char *a, char *b);
int main(void) {
  char x = 0;
  g(&x, &x);
  return 0;
}
```

Frama-C libc triggers (`stpncpy.c` and `strlcat.c`):

```c
#include <string.h>
int main(void) {
  char d[4];
  stpncpy(d, "ab", 4);
  return 0;
}
```

```c
#include <string.h>
int main(void) {
  char d[8] = "a";
  strlcat(d, "ab", 8);
  return 0;
}
```

```sh
OCAMLRUNPARAM=b frama-c quant.c -e-acsl -debug 1
OCAMLRUNPARAM=b frama-c binop.c -e-acsl -debug 1
OCAMLRUNPARAM=b frama-c stpncpy.c -e-acsl -debug 1
OCAMLRUNPARAM=b frama-c strlcat.c -e-acsl -debug 1
```

(The same crash occurs with `e-acsl-gcc -L -c` on `stpncpy.c` and `strlcat.c`, where `-L` enables
Frama-C's libc headers.)

### Expected behaviour

Each command exits 0, emits the standard `E-ACSL construct ... is not yet supported. Ignoring
annotation.` warning for the unsupported clause, and finishes translating the remaining annotations
in the program.

### Additional information (optional)

**Cause.** `plugins/e-acsl/src/analyses/typing.ml` already takes care to type every sibling subterm
or subpredicate after an `Error.Not_yet` in `TUnOp LNot` (lines 380-392), `Tapp` (`type_args`, lines
531-542), and `Prel`/`Pand`/`Por`/`Pxor`/`Pimplies`/`Piff` (`do_both`, lines 783-784, 817-834),
because `Labels.preprocess` registers `\at`/`\old` terms in all subtrees for
`Translate_ats.for_stmt` and `Loops.mk_nested_loops` translates quantifier goals before bounds.

However, the remaining composite cases in `typing.ml` still short-circuit on the first
`Error.Not_yet` / `Error.Typing_error` (either when computing a typing context via `Interval` or
when typing children sequentially):

- `Pforall`/`Pexists` (lines 845-851) and `type_bound_variables` (lines 774-779) abort before typing
  remaining guards and `goal`, triggering both `quant.c` and `stpncpy` (`share/libc/string.h:638`,
  `ensures dest_nul_padded: \forall integer i; strlen(src) <= i < n ==> dest[i] == 0;`, leaving
  `\old(dest)`'s alignment guard `\aligned(dest, 1)` untyped);
- `TBinOp` (lines 404-460, 502-507) aborts after `t1` before typing `t2`, triggering both `binop.c`
  and `strlcat` (`share/libc/string.h:549`, `ensures bounded_result: \result == strlen(dest) + strlen(src);`,
  leaving `\old(src)`'s alignment guard `\aligned(src, 1)` untyped);
- the same pattern occurs in `TUnOp (Neg | BNot)`, `TCast`, `Tif`, `Trange`, `Tlet`, `Pif`, `Plet`,
  `Papp`, `Pseparated`, and `Paligned`.

This is distinct from #2806 (!37), which normalizes lookup keys in `Typing`'s getters: building and
installing !37 on `189053d4a2` still reproduces the exact same exit-4 crashes on `quant.c`,
`stpncpy.c`, and `strlcat.c`.

**Fix.** Use shared `do_both`, `do_all`, and `with_opt_ctx` helpers in `typing.ml` so every sibling
subterm, bound, and quantifier goal is typed before re-raising the first `Error.Not_yet` /
`Error.Typing_error`. A merge request with this fix and a regression test
(`plugins/e-acsl/tests/constructs/typing_unsupported_sibling.c`) is ready.

The analysis and fix were prepared with LLM assistance; I reviewed them and ran the reproducer and
tests described above.
