## Problem

For a pointer to an incomplete (opaque) struct or union, E-ACSL emits `sizeof(T)` or
`__alignof__(T)` of the incomplete type, and the instrumented code does not compile:

- `\valid(obj)`, `\valid_read(obj)` and `\initialized(obj)` use the size of the pointed type
  (`term_to_ptr_and_size` with `Smart_exp.ptr_sizeof`, `range_to_ptr_and_size` with `TSizeOf`);
- the RTE assertion `\aligned(p, alignof(T))` generated by `-rte` for a cast to `T *` is typed and
  translated as is.

E-ACSL already checks `Cil.isCompleteType` for its own alignment and pointer guards in
`rte_analysis.ml`, and warns instead; these terms have no such check.

## Change

- `plugins/e-acsl/src/analyses/typing.ml`: `TSizeOf`/`TAlignOf` of an incomplete struct or union
  raise `Error.not_yet "sizeof or alignof of an incomplete type"`. This covers the RTE alignment
  assertion and user-written `sizeof`/`alignof`.
- `plugins/e-acsl/src/code_generator/memory_translate.ml`: new `check_complete_pointee`, called in
  `term_to_ptr_and_size` and `range_to_ptr_and_size` before any statement is generated, raises
  `Error.not_yet "memory predicate on a pointer to an incomplete type"`. The check cannot sit in
  typing: translating `\valid` does not consult the typing errors of the predicate.

The annotation is ignored with the usual "is not yet supported. Ignoring annotation." warning, and
the rest of the program is instrumented. `void` and function types are left out of both checks:
`sizeof(void)` is accepted by gcc and clang, so `\valid` on a `void *` keeps working.

Regression test: `plugins/e-acsl/tests/constructs/incomplete_type.c` (an opaque `typedef struct
opaque opaque;`, `requires \valid_read(obj)` and `requires \initialized(obj)` on a pointer to it,
and a cast from `void *` that gets an RTE alignment assertion with `-rte`), with its
default-configuration oracles `incomplete_type.0.res.oracle` and `gen_incomplete_type.0.c`. On
`master` the `dev` run of this test fails to compile the instrumented code; with the patch the
three annotations are ignored with the warning, and it builds and runs.

## Testing

On `3dff90fc70` (Debian 13, OCaml 5.5 switch, gcc 14.2.0), with the patch built and installed:

| Check | `master` | Patched |
|---|---|---|
| `e-acsl-gcc` on `requires obj == \null \|\| \valid_read(obj);` (opaque `obj`) | `invalid application of 'sizeof' to incomplete type`, does not build | warning, builds, runs, exit 0 |
| same with `\valid(obj)` and with `\initialized(obj)` | does not build | warning, builds, runs, exit 0 |
| `e-acsl-gcc -F -rte` on a cast `(json_object *)p` | `invalid application of '__alignof__' to incomplete type`, does not build | warning, builds, runs, exit 0 |
| the four programs above with `-G clang` (clang 19.1.7) | does not build (`sizeof`/`alignof` of an incomplete type) | builds, runs, exit 0 |

- ptests `plugins/e-acsl/tests`, default configuration (198 results with the new test): only the
  two new oracles; promoted, and the rerun passes. `dev` configuration (every test compiled and
  run): passes with the patch, the new test included.
- `make check-lint` on the 5 changed files (`LINTCK_FILES_INPUT`, ocp-indent 1.10.0): clean.
  `clang-format` was not installed, so the indentation of the new C test file was not checked.
- `git diff --check`: clean except trailing spaces in the new `.res.oracle` (`Warning: ` lines)
  and the blank line at the end of the new `gen_*.c`, as in every E-ACSL oracle.
- `make check-headers`: not run.

Other options for the maintainers: RTE could skip `pointer_alignment` when the target type is
incomplete (the typing check would still be needed for user-written `sizeof`/`alignof`), and for
`\valid(obj)` E-ACSL could check that `obj` points into an allocated block instead of dropping the
annotation.

reproducer and tests described above.
