Closes #2805.

## Problem

For an incomplete non-void, non-function type (an opaque struct or union, an unsized array such
as `extern int a[]`, or a forward-declared enum), E-ACSL emits `sizeof(T)` or `__alignof__(T)`
of the incomplete type, and the instrumented code does not compile:

- `\valid(obj)`, `\valid_read(obj)` and `\initialized(obj)` use the size of the pointed type
  (`term_to_ptr_and_size` with `Smart_exp.ptr_sizeof`, `range_to_ptr_and_size` with `TSizeOf`);
- the RTE assertion `\aligned(p, alignof(T))` generated by `-rte` for a cast to `T *` is typed and
  translated as is;
- user-written `sizeof(T)`, `alignof(T)`, and expression forms `sizeof(e)` (`TSizeOfE`) or
  `TAlignOfE` on an expression of incomplete type emit `sizeof`/`__alignof__` of that incomplete
  type.

E-ACSL already checks `Cil.isCompleteType` for its own alignment and pointer guards in
`rte_analysis.ml`, and warns instead; these terms have no such check.

## Change

- `plugins/e-acsl/src/analyses/typing.ml`: `TSizeOf`, `TAlignOf`, `TSizeOfE`, and `TAlignOfE` of
  an incomplete non-void, non-function type raise
  `Error.not_yet "sizeof or alignof of an incomplete type"`. For `TSizeOfE`/`TAlignOfE`, the
  operand type is inspected via `Ast_types.Acsl.unroll t'.term_type` before typing `t'`. This
  covers the RTE alignment assertion, user-written `sizeof(T)`/`alignof(T)`, and expression forms
  such as `sizeof(g)` (opaque struct global) and `sizeof(a)` (`extern int a[]`).
- `plugins/e-acsl/src/code_generator/memory_translate.ml`: new `check_complete_pointee`, called in
  `term_to_ptr_and_size` and `range_to_ptr_and_size` before any statement is generated, raises
  `Error.not_yet "memory predicate on a pointer to an incomplete type"`. The check cannot sit in
  typing: translating `\valid` does not consult the typing errors of the predicate.

The annotation is ignored with the usual "is not yet supported. Ignoring annotation." warning, and
the rest of the program is instrumented. `void` and function types are left out of both checks:
`sizeof(void)` is accepted by gcc and clang, so `\valid` on a `void *` keeps working.

Regression test: `plugins/e-acsl/tests/constructs/incomplete_type.c` (an opaque `typedef struct
opaque opaque;` with `extern opaque g;`, an unsized `extern int a[];`, a complete `struct complete
complete_var;` control, `requires \valid_read(obj)` and `requires \initialized(obj)` on a pointer
to `opaque`, a cast from `void *` that gets an RTE alignment assertion with `-rte`, plus
`assert sizeof(g) > 0;`, `assert sizeof(a) > 0;`, `assert alignof(int[]) > 0;`, and positive
control `assert sizeof(complete_var) > 0;`), with its default-configuration oracles
`incomplete_type.0.res.oracle` and `gen_incomplete_type.0.c`. On `master` both the default and
`dev` runs of this test fail (the `dev` run fails to compile the instrumented code); with the
patch the incomplete-type annotations are ignored with the warning, the complete-type assertion
is translated and checked, and it builds and runs.

## Testing

On `b80fcac74f` (Debian 13, OCaml 5.5 switch, gcc 14.2.0, clang 19.1.7), with the patch built and
installed:

| Check | `master` (`b80fcac74f`) | Patched |
|---|---|---|
| `e-acsl-gcc` on `requires obj == \null \|\| \valid_read(obj);` (opaque `obj`) | `invalid application of 'sizeof' to incomplete type`, does not build | warning, builds, runs, exit 0 |
| `e-acsl-gcc -F -rte` on a cast `(json_object *)p` | `invalid application of '__alignof__' to incomplete type`, does not build | warning, builds, runs, exit 0 |
| `e-acsl-gcc` on `sizeof(g)` (opaque struct global), `sizeof(a)` (`extern int a[]`), and `sizeof(complete_var)` | `invalid application of 'sizeof' to incomplete type 'struct opaque'` and `'int[]'`, does not build | warnings on `g`/`a`, complete control checked, builds, runs, exit 0 |
| the three programs above with `-G clang` (clang 19.1.7) | does not build (`sizeof`/`alignof` of an incomplete type) | builds, runs, exit 0 |

- `./dev/test.sh -p plugins/e-acsl/tests/constructs/incomplete_type.c` (default and `-c dev`):
  fails on `master` sources (both default and `dev`), passes with the patch (both default and
  `dev`).
- `./dev/test.sh -p plugins/e-acsl` (default configuration, full E-ACSL suite): passes with the
  patch.
- `./dev/check-files.sh -p HEAD~1` (5 changed files, `ocp-indent` 1.10.0, `clang-format` 19.1.7):
  clean (exit 0).

Other options for the maintainers: RTE could skip `pointer_alignment` when the target type is
incomplete (the typing check would still be needed for user-written `sizeof`/`alignof`), and for
`\valid(obj)` E-ACSL could check that `obj` points into an allocated block instead of dropping the
annotation.

reproducer and tests described above.
