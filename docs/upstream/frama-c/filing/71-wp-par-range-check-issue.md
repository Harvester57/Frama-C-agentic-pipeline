# [WP] `-wp-par 0` (and negative values) crash with `Invalid_argument("Prove_client.set_max_running_provers")`

<!-- Everything below this line is the issue description. -->

### Summary

The `-wp-par` option (`Wp_parameters.Procs`, `plugins/wp/src/wp_parameters.ml:862-870`) is an unbounded `Int` parameter with no `set_range`. Passing `-wp-par 0` or any negative value (`-wp-par -1`) passes command-line validation and crashes inside Why3's `Prove_client.set_max_running_provers` with `Unexpected error (Invalid_argument("Prove_client.set_max_running_provers"))` (exit code 125).

### Steps to reproduce the issue

`par_repro.c`:

```c
/*@ requires x > 0;
    ensures \result > 0; */
int f(int x) {
  return x + 1;
}
```

```sh
OCAMLRUNPARAM=b frama-c -debug 1 -wp -wp-rte -wp-par 0 par_repro.c
frama-c -wp -wp-rte -wp-par -1 par_repro.c
```

### Expected behaviour

`-wp-par 0` and `-wp-par -1` should be rejected at command-line parsing time with `[wp] User Error: argument of -wp-par must be at least 1.` and exit code 1, without an uncaught exception.

### Contextual information

- Frama-C installation mode: from source (`master`) and opam (Docker image based on `framac/frama-c:dev`)
- Frama-C version: 35.0~~dev (Bromine), `master` at `189053d4a2`; also 34.0~beta (Selenium), with identical output
- Plug-in used: WP
- OS name: Debian GNU/Linux
- OS version: 13 (trixie; glibc 2.41, gcc 14.2.0)

### Additional information (optional)

**Cause.** `plugins/wp/src/wp_parameters.ml:862-870` (commit `189053d4a2`) defines `Procs` as an `Int` option without calling `Procs.set_range`, so `0` or negative values pass CLI parsing (and `wpApi.ml:139`) directly into `ProverTask.server` (`ProverTask.ml:28`) -> `Why3Env.set_procs` -> `Prove_client.set_max_running_provers`, which requires `>= 1`.

**Fix.** Add `let () = Procs.set_range ~min:1 ~max:max_int` in `plugins/wp/src/wp_parameters.ml`. A merge request follows.

The analysis and fix were prepared with LLM assistance; I reviewed them and ran the reproducer and tests described above.
