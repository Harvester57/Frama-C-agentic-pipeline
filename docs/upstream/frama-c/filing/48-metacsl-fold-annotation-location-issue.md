# [MetAcsl] `-meta-fold` drops the location of the folded instances

<!-- Everything below this line is the issue description. Tracker: pub/meta (MetAcsl), not pub/frama-c. -->

### Summary

With `-meta-fold`, a folded instance is an assertion that calls the generated predicate, and this
assertion has no source location: the report shows it as "generated by Frama-C kernel", WP goals
too, and E-ACSL reports its failure at `<unknown>:0`. The same property left unfolded (with
`\flags(fold:no)`) in the same run keeps the line of the meta property. A user who turns on
`-meta-fold` for E-ACSL, as the README suggests to cut its compilation time, gets failures that no
longer say which property line they come from (the property name is still there).

The same loss happens without `-meta-fold` in two cases: under `-meta-quantify-range`, when a
`\written` or `\read` range from a callee's contract becomes a `\forall`, and when the callee's
`assigns` sits in a behavior with `assumes`.

### Steps to reproduce the issue

`fold.c`:

```c
/* -meta-fold drops the location of the folded instances.
 *
 * Two identical \writing properties: auth_folded is folded by -meta-fold,
 * auth_unfolded stays unfolded through \flags(fold:no). Both are violated:
 * "./prog folded" writes auth_ok through hack, "./prog" through bump.
 */
int auth_ok;

void hack(int *p)
{
  *p = 1;
}

void bump(int *p)
{
  *p = 1;
}

int main(int argc, char **argv)
{
  (void)argv;
  if (argc > 1)
    hack(&auth_ok);
  else
    bump(&auth_ok);
  return 0;
}

/*@ meta \prop, \name(auth_folded), \targets({hack}), \context(\writing),
      \separated(\written, &auth_ok);
*/

/*@ meta \prop, \name(auth_unfolded), \targets({bump}), \context(\writing),
      \flags(fold:no),
      \separated(\written, &auth_ok);
*/
```

```
$ frama-c fold.c -meta -meta-fold -then-last -report
$ frama-c fold.c -meta -meta-fold -then-last -e-acsl -then-last -print -ocode out.c
$ e-acsl-gcc -C -c out.c -O prog
$ ./prog.e-acsl folded
$ ./prog.e-acsl
```

`-print` gives `/*@ assert auth_folded: meta: meta_auth_folded(p); */` in `hack` and
`/*@ assert auth_unfolded: meta: \separated(p, &auth_ok); */` in `bump`, as expected.

### Expected behaviour

The folded assertion has the location the unfolded one has, the line of the property's predicate
(30 for `auth_folded`, 35 for `auth_unfolded`). Without `-meta-fold`,
`frama-c fold.c -meta -then-last -report` gives:

```
[ Partial ] Meta auth_folded ("fold.c", lines 29-30)
            By auth_folded, with pending:
             - Assertion 'meta' ("fold.c", line 30)
[ Partial ] Meta auth_unfolded ("fold.c", lines 33-35)
            By auth_unfolded, with pending:
             - Assertion 'meta' ("fold.c", line 35)
```

With `-meta-fold` and the change proposed below, the report gives the same output and E-ACSL
reports the failure of `hack` as:

```
fold.c: In function 'hack'
fold.c:30: Error: Assertion failed:
```

### Actual behaviour

The report:

```
[ Partial ] Meta auth_folded ("fold.c", lines 29-30)
            By auth_folded, with pending:
             - Assertion 'meta' (generated by Frama-C kernel)
[ Partial ] Meta auth_unfolded ("fold.c", lines 33-35)
            By auth_unfolded, with pending:
             - Assertion 'meta' ("fold.c", line 35)
```

The E-ACSL translation warns at no location either:

```
[e-acsl] <generated by Frama-C kernel>: Warning: 
  no assigns clause generated for function meta_auth_folded because pointers as arguments is not yet supported
```

`./prog.e-acsl folded` (the folded property):

```
<unknown>: In function 'hack'
<unknown>:0: Error: Assertion failed:
	The failing predicate is:
	auth_folded/meta:
		meta_auth_folded(p).
	With values at failure point:
	- auth_folded: meta: meta_auth_folded(p): 0
	- p: 0x600a05629254
Aborted
```

`./prog.e-acsl` (the unfolded property):

```
fold.c: In function 'bump'
fold.c:35: Error: Assertion failed:
	The failing predicate is:
	auth_unfolded/meta:
		\separated(p, &auth_ok).
	With values at failure point:
	- auth_unfolded: meta: \separated(p, &auth_ok): 0
	- &auth_ok: 0x58993e9e7254
	- sizeof(int): 4
	- p: 0x58993e9e7254
Aborted
```

MetAcsl's own tests record it: in `tests/meta-wp/oracle_fold/typing.0.res.oracle` the goal reads
`Goal Assertion 'test,meta' (generated by Frama-C kernel):`, and in
`tests/meta-wp/oracle/typing.0.res.oracle` it reads `Goal Assertion 'test,meta' ("typing.c", line 22):`.

### Contextual information

- Frama-C installation mode: opam (Docker image)
- Frama-C version: 34.0~beta (Selenium), with MetAcsl 0.12~beta
- MetAcsl `master` (`4f43801390`): built on the same 34.0~beta with one line removed from
  `meta_parse.ml` (the `PLpointer_comparable` case, a constructor 34.0~beta does not have yet), and
  installed in place of 0.12~beta. It gives the same output as above.
- OS name: Debian GNU/Linux
- OS version: 13 (trixie)

### Additional information (optional)

- **Where the location is dropped.** In `meta_annotate.ml`, `create_call` builds the call to the
  folded predicate with `Logic_const.papp (li,labels,args)`, without `~loc`, so the predicate gets
  the default `Kernel.gen_loc`. `create_instance` uses it for every folded instance. An unfolded
  instance is the predicate returned by `ump_property`, which keeps the location of the parsed
  property. The property name is not affected: it is added later by `name_mp_pred`, the same way
  in both modes. `\precond`, `\postcond`, `\weak_invariant` and `\conditional_invariant`
  properties are not affected either: they go through `add_to_contract`, which never folds.
- **The two other cases.** In `external_assigns` (writing) and `passthrough_from` (reading), the
  instance is wrapped by `post` (an implication from the `assumes` of the callee's behavior) and
  by `post_fold` (the `\forall` of `-meta-quantify-range`). Both use `Logic_const.pimplies` and
  `Logic_const.pforall` without `~loc`, so the wrapped instance loses its location, folded or not.
  With `/*@ assigns p[0 .. n-1]; */ void fill(int *p, int n);` called as `fill(&auth_ok, 1)` in a
  target, `-meta-quantify-range` alone gives E-ACSL `file = "<unknown>"` and `line = 0` for the
  instance, where the run without the option gives the file and the line of the property.
- **A possible change.** Pass `~loc:inst.pred_loc` to the call in `create_instance`, and
  `~loc:prop.pred_loc` to the `pimplies` of `post` and the `pforall` of `post_fold` in both
  visitors. I tested it on the build of `master` described above: the report and E-ACSL then give
  `fold.c:30` for `auth_folded`, the two other cases get the property's line, and the `meta`,
  `meta-wp` and `meta-deduce` suites give the same results as `master` in both configurations
  (SWI-Prolog is not installed on my setup, so the deduction checks of `meta-deduce` fail the same
  way with and without it), except the fold oracle of `meta-wp/typing.c` quoted above, which then
  reads `("typing.c", line 22)`. I am sending it as a merge request that refers to this issue.
