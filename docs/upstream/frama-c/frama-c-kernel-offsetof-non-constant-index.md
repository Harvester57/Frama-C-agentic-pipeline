# Kernel: `offsetof(T, m[i])` with a non-constant index (GCC/Clang extension) aborts the parsing

**Filed upstream on 2026-11-15:** issue [#2813](https://git.frama-c.com/pub/frama-c/-/work_items/2813), merge request [!44](https://git.frama-c.com/pub/frama-c/-/merge_requests/44).

Draft feature request for the Frama-C issue tracker (https://git.frama-c.com/pub/frama-c/-/issues).
Not filed yet at the time of writing; see the filing note at the top. Issue 25 of this folder.

**Filing package:** [issue](./filing/25-kernel-offsetof-non-constant-index-issue.md), [MR](./filing/25-kernel-offsetof-non-constant-index-mr.md), [reproducer](./repro/25-kernel-offsetof-non-constant-index.sh), [patch](./patches/25-kernel-offsetof-non-constant-index.patch)

## Summary

GCC and Clang accept `offsetof(T, m[i])` with a variable `i` and compute the offset at run time.
Frama-C stops the parsing:

```
[kernel] t.c:14: User Error:
  Unable to compute offset .args[i] in type struct s: Index is not constant
```

Found on libseccomp: `src/arch.c:54` defines `default_arg_offset(x)` as
`offsetof(struct seccomp_data, args[x])`, used with a variable at `src/arch.c:267` (see the
`offsetof` entry of
[`../../troubleshooting/kernel-and-stubs.md`](../../troubleshooting/kernel-and-stubs.md)).

### Bug or feature request

A feature request. C17 7.19p3 says `offsetof(type, member-designator)` expands to an integer constant
expression and that `&(t.member-designator)` must evaluate to an address constant, so a
non-constant index is outside ISO C. GCC documents `__builtin_offsetof` with a `[ expr ]`
designator and evaluates it at run time; Clang follows. `gcc -Wall -Wextra -pedantic` does not warn.
Frama-C already accepts the designator in its grammar (`offsetof_member_designator`, "GCC extension
for __builtin_offsetof", `src/kernel/internals/parsing/cparser.mly:586-591`), so supporting the
non-constant case completes an extension it already parses.

### Cause

`src/kernel/internals/typing/cabs2cil.ml:6962-6986` on `3dff90fc70` folds the whole designator
with `Cil.bitsOffset`, which raises `SizeOfError "Index is not constant"` on the first
non-constant index (`src/kernel/services/ast_queries/cil.ml:3645`); the handler reports it with
`Kernel.error`, and the file is rejected.

## Fix

[`./patches/25-kernel-offsetof-non-constant-index.patch`](./patches/25-kernel-offsetof-non-constant-index.patch),
one commit on `fix/offsetof-non-constant-index` from `3dff90fc70`, "[kernel] offsetof: accept
non-constant array indexes (GCC extension)". In the `__builtin_offsetof` case of the typer, each
non-constant index of the designator is replaced by 0, the resulting constant offset is folded
with `Cil.bitsOffset` as before, and `(size_t)i * sizeof(element)` is added for each replaced
index. Constant designators give the same constant as before. New test
`tests/syntax/offsetof_non_constant_index.c`.

Output with the fix:

```
--- gcc: compiles and runs, exit 0
--- frama-c -print
  __retres = 128UL + (unsigned long)i * 8UL;
  __retres = (16UL + (unsigned long)i * 40UL) + (unsigned long)j * 8UL;
--- Eva (-warn-invalid-pointer): 0 alarms generated by the analysis.
--- WP (-wp-rte, Alt-Ergo): [wp] Proved goals:   13 / 13
RESULT: fixed
```

Open questions for the maintainers (in the issue): accept silently as GCC does or warn, and whether
to restrict it to GCC-like machdeps.

## Workaround

The pipeline rewrites the preprocessed file: [`../../../scripts/fc_cpp_wrapper.py`](../../../scripts/fc_cpp_wrapper.py)
(a gcc `-wrapper`) turns `__builtin_offsetof(T, m[i])` into
`(__builtin_offsetof(T, m) + (__typeof__(sizeof(0)))(i) * sizeof((((T *)0)->m)[0]))` after
`cc1 -E`, only when an index is not an integer literal. That is the same elaboration as the patch,
done textually. Redefining `offsetof` as `((size_t)&((T *)0)->m)` was rejected: the kernel no longer
folds it, Eva with `-warn-invalid-pointer` reports the null-based address as invalid, WP cannot
prove offsets, and `_Static_assert` on an offset stops the parsing.
